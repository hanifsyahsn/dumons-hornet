## Commands

```bash
npm run dev        # nodemon: full rebuild (client + server) and restart on any src/ change; no HMR, reload the browser
npm run build      # webpack client -> dist/client, server -> dist/server
npm start          # production server from dist/server/server.js (build first)
npm run build:static  # production build + prerender every route into dist/static (what Netlify runs)
npm run typecheck  # tsc --noEmit; the only static check (no linter, no tests)
```

`.env` (copy from `.env.example`) holds `PORT` (default 3000) and optionally `MAINTENANCE_MODE` (build time, see Routing).

Commits are titled `[development][x.y.z] summary` (semver: minor for a feature, patch for a fix). Bump `package.json` to the same version in that commit with `npm version x.y.z --no-git-tag-version` (it updates `package-lock.json` too).

## Architecture

React 19 SSR with two webpack builds sharing the same `src/`:

- **Server** (`webpack.server.js`, entry `src/server/server.tsx`, `target: node`, CSS imports ignored via `ignore-loader`): Express serves `dist/client` and `public/` statically, redirects `/` → `/home`, and renders every other path via `renderPage`. The full HTML document (head, favicon, loader markup) is a template string in `render.tsx`, not a React component; per-page `<title>` comes from the route's `title`.
- **Client** (`webpack.client.js`, entry `src/client/index.tsx`): `hydrateRoot` inside `BrowserRouter`; all CSS is extracted by `MiniCssExtractPlugin` into one stylesheet. Bundle and stylesheet are content-hashed (`/_app/bundle.<hash>.js`, `/_app/styles.<hash>.css`) so a page only ever loads the files built with it (a cached old `bundle.js` next to newer HTML used to fail hydration and leave buttons dead until a refresh); `webpack.client.js` writes their names to `dist/client-assets.json`, which `render.tsx` reads. Prerender adds a `_headers` file caching `/_app/*` for a year (`immutable`; HTML keeps Netlify's revalidate-every-time default) and copies the files to the old `/bundle.js` and `/styles.css` names for HTML cached before the switch.

Rendering is shared: `src/server/render.tsx` (`renderPage(url)`) renders the app and wraps it in the HTML document. It is used by both `server.tsx` (per request) and `src/server/prerender.tsx` (build time; second entry in `webpack.server.js`). Prerender copies `dist/client` + `public/` into `dist/static`, writes each route as `<path>.html` (so Netlify serves `/home` from `home.html`), renders `404.html` via the `*` route, writes `sitemap.xml`/`robots.txt`, and writes `_redirects` (`/` → default route, maintenance catch-all, plus any `context.url` redirects). Routes with params are skipped unless they define `getStaticPaths`. A page with pages under it (`produk.html` next to `produk/`) also gets an explicit 200 rewrite in `_redirects`. Keep anything request-dependent out of pages, since production HTML is generated once per deploy. Page paths are constants there too (`HOME_PATH`, `PRODUCTS_PATH`, `productPath(slug)`), as is the 404 title. SEO lives in `src/seo.ts`: a route's `head` (an object or a function of the URL params) gives its `<title>`, meta description, preview image and schema.org JSON-LD, merged over the site defaults by `pageHead()` in `routes.ts`, which `render.tsx` writes into `<head>` (canonical, `index, follow, max-image-preview:large`, Open Graph + `summary_large_image` Twitter card, one `application/ld+json` script per object; 404s get `noindex` only) and `App.tsx` uses for `document.title` on client-side navigation (NotFound sets its own). Copy: `seo` in `home.json` (site default and /home), `page.seoTitle`/`seoDescription` in `products.json` (/produk); detail pages build theirs from the product (`name – tagline, N Warna | Dümons Coating`, the description's first sentence plus the color count, its photo, and `Product` + `BreadcrumbList` data with specs as `additionalProperty`). /home adds `Organization` + `WebSite` (and the FAQPage script in `Home.tsx`), /produk a `BreadcrumbList` + `ItemList`. Descriptions are clipped at a word boundary to 160 characters; the sitemap carries the build date as `lastmod`. The `/` redirect target is `DEFAULT_PATH` (`src/constants/routing.ts`), used by `server.tsx`, `App.tsx`, `NotFound` and prerender's `_redirects`.

Routing: `src/routes.ts` is the list of `{ path, component }` rendered by `src/pages/App.tsx` (which also redirects `/` for client-side navigation). Keep the `*` catch-all last.

Maintenance mode (`src/constants/routing.ts`): `MAINTENANCE_MODE=true` at build time (baked into both bundles by webpack `DefinePlugin`, so changing it needs a rebuild) filters `routes` down to `/under-construction` + `*`, makes it `DEFAULT_PATH` (otherwise `/home`), and redirects every other path there: `server.tsx` per request, and on Netlify via `_redirects` (an explicit 200 rewrite for the page, then `/* → /under-construction 302`, which existing files shadow). The flag is not kept in git (no `netlify.toml` entry): when `MAINTENANCE_MODE` is unset, builds with `BRANCH=production` (set by Netlify) default to on; set `MAINTENANCE_MODE=false` in the Netlify UI environment variables to launch.

HTTP status/redirects from SSR: pages receive an optional `context: RouteContext` prop (only on the server). Setting `context.status = 404` (as `NotFound` does) or `context.url` (301 redirect) is read by `server.tsx` after rendering. The `<title>` is chosen in `server.tsx` based on that status.

Loading overlay: `render.tsx` emits a static `#server-loader` overlay that `client/index.tsx` removes from an effect (`LiftLoader`), i.e. only once hydration has committed, not right after the `hydrateRoot` call, which returns before React has hydrated anything; it covers the page so nothing can be tapped before React is ready (taps on the menu or carousel buttons before the bundle ran did nothing, while plain links like "Lihat produk" worked). It is styled by plain CSS inline in `<head>`, never Tailwind (older Safari drops Tailwind's `@layer` and `oklab()`, which left the overlay transparent), and fades out by itself after 10s if the bundle never runs. The bundle is a `defer` script in `<head>` with `fetchpriority="high"` (Chrome otherwise fetches defer scripts at low priority, behind the page's images, which on a slow first visit kept buttons dead for seconds after the loader lifted). A button tapped before the bundle runs is remembered by an inline script in `render.tsx` (`window.__earlyTap`, until `client/index.tsx` sets `__reactListening`) and replayed by `LiftLoader` once React is ready. `src/components/loading` provides a matching React overlay via `useLoading()`. For phones we can't test on, any page opened with `?debug` shows a box listing the user agent, when hydration finished, every click, and every error (window errors, React's recoverable/caught/uncaught errors; an inline script in `render.tsx` reports errors raised before the bundle runs, such as a parse error); without `?debug` nothing changes.

## Styling

PostCSS pipeline (`postcss.config.js`): `postcss-import` → Tailwind v4 → `postcss-custom-media` → `postcss-nesting` → `postcss-media-minmax` → autoprefixer. Nesting and `(width > …)` media ranges are flattened to plain CSS on purpose: older browsers (iOS < 16.5, Chrome < 112, many in-app WebViews) drop nested rules and range queries, which broke the phone menu and the review carousel there; give anything newer (container units like `cqi`, `svh`/`dvh`) a plain fallback declaration before it. `src/styles/global.css` imports Tailwind and `variables.css`.

- Visual style is neo-brutalism: thick ink borders, hard shadows with no blur, action elements skewed `-12deg` like the logo frame, no border radius.
- Design tokens live in `src/styles/variables.css` (`--hornet-*` colors, `--border*`, `--shadow-*`, `--skew`, `--container`/`--gutter` (both grow on large monitors), `--font-display`/`--font-body`, `--fs-*` sizes). The hero title is sized in `cqi` from its own column (`container-type: inline-size`), so it never runs into the photo.
- `src/components/shell` is the page frame (sticky fixed-height header with the logo and the site nav (`nav` prop overrides `SITE_NAV`; `[]` for logo only), thin hazard strip, dark footer with the social links in `SOCIALS`). The header never changes height, so `scroll-padding-top` in `global.css` (96px) lands anchors right under it; `body` uses `overflow-x: clip` (not `hidden`, which would break `position: sticky`) and defines the shared `.hazard` strip and skewed `.button` (`--sm`/`--lg`/`--xl`, `--yellow`/`--dark`/`--white`; works on `<a>` and `<button>`). Home and NotFound share the `.hero` styles in `src/pages/home/styles.css`. The Hornet palette (yellow `#ffff00`, ink `#271b1d`, white, orange accent) is sampled from `public/assets/logo-bordered.webp`; keep new colors on these tokens.
- Responsive breakpoints are `@custom-media` queries (`--small`, `--medium`, ...) used as `@media (--medium)`, nested inside BEM-style class blocks (e.g. `.construction__title`).
- Tailwind utilities are used mainly for the loader markup.

`src/components/mascot` is the hornet mascot: the logo hornet itself, traced from `logo.webp` into `paths.ts` by `scripts/trace-mascot.py` (Python + potrace; rerun it when the logo changes, never hand-edit the paths), with the wings as a separate part so they can flap. Die-cut white outline + hard ink shadow via stacked `drop-shadow`s, animated in CSS (bob, wing flap, speed lines); all motion, including the ticker, stops under `prefers-reduced-motion`.

Brand constants are in `src/constants/brand.ts` (logo paths, site and main-site URLs in code; WhatsApp, email, Shopee and Instagram re-exported from `contact` in `home.json`); logos live in `public/assets/` (`logo-bordered.webp`, shown as its 600px copy `logo-bordered-600.webp` in header/footer with a hard black `drop-shadow` backing (on `/home` the header logo scrolls back to the top and clears any `#section` from the URL; on other pages it links to `/home`), `logo.webp` (square hornet mark) as the photo placeholder and schema.org logo, its 192px copy `logo-192.webp` as favicon and reviews stamp, `logo-borderless.webp` unused).
